## 1. Objective

Replace the placeholder `GET /api/v1/health` that returns `{"status": "ok"}` with a full health check that reports:

- Overall service status (`healthy` / `degraded` / `unhealthy`).
- Whether the YOLO model is loaded and ready.
- GPU availability and device name.
- Free disk space on the storage volume.

This endpoint is used by Docker HEALTHCHECK, load balancers, and monitoring systems.

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                  |
| ---- | ----------------------------------------------------------------------------------------- |
| AC-1 | `GET /api/v1/health` returns `200` with model, GPU, and disk status.                      |
| AC-2 | `status` is `"healthy"` when model is loaded and disk has >1 GB free.                     |
| AC-3 | `status` is `"degraded"` when GPU is requested but unavailable (running on CPU fallback). |
| AC-4 | `status` is `"unhealthy"` when model is not loaded or disk has <1 GB free.                |
| AC-5 | `model_loaded` reflects whether `get_detector()` has been initialized.                    |
| AC-6 | `gpu_available` and `gpu_name` reflect CUDA status.                                       |
| AC-7 | `disk_free_gb` reports free space on the storage partition.                                |
| AC-8 | Endpoint responds in <200ms (no heavy computation).                                       |
| AC-9 | Endpoint never raises an exception — always returns a JSON response.                       |

## 3. Detailed Implementation

### 3.1 Response Schema — `app/models/schemas.py`

Add the health response model:

```python
class HealthResponse(BaseModel):
    """Response for GET /api/v1/health."""
    status: str  # "healthy", "degraded", "unhealthy"
    model_loaded: bool
    gpu_available: bool
    gpu_name: str | None = None
    disk_free_gb: float
```

---

### 3.2 Router Implementation — `app/routers/health.py`

```python
import shutil
import logging

import torch
from fastapi import APIRouter

from app.config import settings
from app.models.schemas import HealthResponse

logger = logging.getLogger(__name__)

router = APIRouter()

# Minimum free disk space before reporting unhealthy (1 GB)
MIN_DISK_FREE_GB = 1.0


@router.get("/health", response_model=HealthResponse)
async def health_check():
    """Check service health: model, GPU, and disk status.

    Returns:
        - healthy: Model loaded, disk OK.
        - degraded: Running but with issues (e.g. CPU fallback when GPU expected).
        - unhealthy: Model not loaded or disk critically low.
    """
    model_loaded = _check_model_loaded()
    gpu_available = torch.cuda.is_available()
    gpu_name = torch.cuda.get_device_name(0) if gpu_available else None
    disk_free_gb = _check_disk_free()

    # Determine overall status
    status = _determine_status(model_loaded, gpu_available, disk_free_gb)

    return HealthResponse(
        status=status,
        model_loaded=model_loaded,
        gpu_available=gpu_available,
        gpu_name=gpu_name,
        disk_free_gb=disk_free_gb,
    )


def _check_model_loaded() -> bool:
    """Check if the detector service has been initialized with a model."""
    try:
        from app.services.detector import _detector
        return _detector is not None
    except Exception:
        return False


def _check_disk_free() -> float:
    """Get free disk space in GB on the storage partition."""
    try:
        usage = shutil.disk_usage(settings.output_dir)
        return round(usage.free / (1024 ** 3), 1)
    except Exception:
        logger.warning("Could not read disk usage for %s", settings.output_dir)
        return 0.0


def _determine_status(
    model_loaded: bool,
    gpu_available: bool,
    disk_free_gb: float,
) -> str:
    """Determine overall health status.

    - unhealthy: model not loaded OR disk < 1 GB
    - degraded:  GPU config is "gpu" but CUDA unavailable (CPU fallback)
    - healthy:   everything OK
    """
    # Unhealthy conditions
    if not model_loaded:
        return "unhealthy"
    if disk_free_gb < MIN_DISK_FREE_GB:
        return "unhealthy"

    # Degraded conditions
    if settings.processing_mode.lower() == "gpu" and not gpu_available:
        return "degraded"

    return "healthy"
```

## 5. Status Decision Matrix

| Model Loaded | GPU Config | GPU Available | Disk Free | Status        |
| ------------ | ---------- | ------------- | --------- | ------------- |
| No           | any        | any           | any       | **unhealthy** |
| Yes          | any        | any           | < 1 GB    | **unhealthy** |
| Yes          | `"gpu"`    | No            | >= 1 GB   | **degraded**  |
| Yes          | `"cpu"`    | No            | >= 1 GB   | **healthy**   |
| Yes          | `"auto"`   | No            | >= 1 GB   | **healthy**   |
| Yes          | any        | Yes           | >= 1 GB   | **healthy**   |

**Key logic:**
- `degraded` only triggers when the user explicitly configured `PROCESSING_MODE=gpu` but CUDA isn't available. If mode is `auto` or `cpu`, lack of GPU is expected behavior — not degraded.

## 7. Design Decisions

| Decision                                        | Rationale                                                                                       |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Always return 200**                            | Health endpoints should return JSON with status info, not HTTP error codes. Load balancers and monitoring tools parse the body. Returning 503 would prevent clients from reading the diagnostic JSON. |
| **`_detector is not None` check**                | Accesses the module-level singleton directly without calling `get_detector()`. This avoids accidentally triggering model loading during a health check. |
| **`shutil.disk_usage` for disk space**           | Standard library, cross-platform (Windows + Linux). No external dependencies.                  |
| **`degraded` only for explicit GPU mismatch**    | Avoids false alarms on CPU-only machines. Only flags when the admin set `PROCESSING_MODE=gpu` but CUDA isn't working. |
| **Never raises exceptions**                      | Each check is wrapped in try/except. A failing disk check shouldn't crash the health endpoint.  |

---

## 8. Notes

- **Model lazy-loading:** The detector model loads on the first `get_detector()` call (triggered by the first job). Before that, `model_loaded` is `false` and status is `unhealthy`. This is expected — the server is up but not yet warm. A startup preload can be added to `lifespan` in the future if needed.
- **Story 6.5 (CORS)** was already implemented in Story 1.3 — no additional work needed.
- **`disk_free_gb` reports the partition where `settings.output_dir` lives.** If uploads and outputs are on different partitions, only the output partition is checked. Good enough for MVP.
- **Extending the health check:** Future fields like `active_jobs`, `uptime_seconds`, or `ffmpeg_available` can be added to `HealthResponse` without breaking existing clients (additive schema change).
