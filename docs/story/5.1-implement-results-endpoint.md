# Story 5.1 — Implement `GET /api/v1/jobs/{job_id}/results`

| Field          | Value                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| **Epic**       | 5 — Results & File Serving                                                                                |
| **Priority**   | P0                                                                                                       |
| **Summary**    | Return structured JSON with segments, bbox, and download links                                            |
| **Depends on** | 4.5 (status endpoint), 2.4 (`PipelineResult` stored in job), 2.2 (`Segment` / `SegmentationResult`)     |
| **Blocks**     | 5.2 (download endpoint uses segment index from this response)                                            |

---

## 1. Objective

Replace the placeholder `GET /api/v1/jobs/{job_id}/results` stub with a fully functional endpoint that returns:

- Video metadata (fps, frame count, duration).
- Detection summary (seconds scanned, seconds with detection).
- List of segments with time ranges, bounding boxes, and download URLs.

This is the endpoint clients call after polling status shows `completed`.

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------ |
| AC-1 | `GET /api/v1/jobs/{job_id}/results` returns `200` with structured JSON matching the PRD API contract (6.3).  |
| AC-2 | Returns `404` if `job_id` does not exist.                                                                    |
| AC-3 | Returns `409` if job is not yet `completed` (queued, processing, failed, cancelled).                         |
| AC-4 | `video_metadata` contains `fps`, `total_frames`, `duration_seconds` from `DetectionResult`.                  |
| AC-5 | `detection_summary` contains `total_seconds_scanned`, `seconds_with_detection` from `SegmentationResult`.    |
| AC-6 | Each segment includes `index`, `start_time`, `end_time`, `start_seconds`, `end_seconds`, `duration_seconds`, `bbox`, and `download_url`. |
| AC-7 | `download_url` is a relative URL in the format `/api/v1/jobs/{job_id}/segments/{index}/download`.            |
| AC-8 | `bbox` is an object with `x_min`, `y_min`, `width`, `height` keys (not a raw array).                        |

## 3. Detailed Implementation

### 3.1 Response Schemas — `app/models/schemas.py`

Add result-related schemas:

```python
class VideoMetadataResponse(BaseModel):
    """Video file metadata."""
    fps: float
    total_frames: int
    duration_seconds: float


class DetectionSummaryResponse(BaseModel):
    """Summary statistics of the detection phase."""
    total_seconds_scanned: int
    seconds_with_detection: int


class BboxResponse(BaseModel):
    """Bounding box in pixel coordinates."""
    x_min: float
    y_min: float
    width: float
    height: float


class SegmentResponse(BaseModel):
    """A single detected segment with download link."""
    index: int
    start_time: str
    end_time: str
    start_seconds: int
    end_seconds: int
    duration_seconds: int
    bbox: BboxResponse
    download_url: str


class JobResultsResponse(BaseModel):
    """Response for GET /api/v1/jobs/{job_id}/results."""
    job_id: str
    status: str
    video_metadata: VideoMetadataResponse
    detection_summary: DetectionSummaryResponse
    segments: list[SegmentResponse]
```

### 3.2 Router Implementation — `app/routers/jobs.py`

Replace the `get_job_results` stub:

```python
from app.models.schemas import (
    JobCreateResponse,
    JobStatusResponse,
    JobProgressResponse,
    JobCancelResponse,
    JobResultsResponse,
    VideoMetadataResponse,
    DetectionSummaryResponse,
    SegmentResponse,
    BboxResponse,
    ErrorResponse,
)
from app.services.pipeline import PipelineResult


@router.get(
    "/jobs/{job_id}/results",
    response_model=JobResultsResponse,
    responses={
        404: {"model": ErrorResponse},
        409: {"model": ErrorResponse},
    },
)
async def get_job_results(job_id: str):
    """Get the detection and segmentation results of a completed job.

    Only available when job status is "completed". For other states:
    - queued/processing → 409 (not ready yet)
    - failed/cancelled → 409 (no results available)
    - not found → 404
    """
    job = job_store.get(job_id)
    if not job:
        raise HTTPException(status_code=404, detail=f"Job '{job_id}' not found")

    if job.status != JobStatus.COMPLETED:
        raise HTTPException(
            status_code=409,
            detail=f"Job '{job_id}' is '{job.status.value}' — results are only available for completed jobs",
        )

    result: PipelineResult = job.result
    if not result:
        raise HTTPException(
            status_code=500,
            detail=f"Job '{job_id}' is completed but result data is missing",
        )

    # Build video metadata
    video_metadata = VideoMetadataResponse(
        fps=result.detection.metadata.fps,
        total_frames=result.detection.metadata.frame_count,
        duration_seconds=result.detection.metadata.duration_seconds,
    )

    # Build detection summary
    detection_summary = DetectionSummaryResponse(
        total_seconds_scanned=result.segmentation.total_seconds_scanned,
        seconds_with_detection=result.segmentation.seconds_with_detection,
    )

    # Build segment list with download URLs
    segments = []
    for seg in result.segmentation.segments:
        bbox = BboxResponse(
            x_min=seg.bbox[0],
            y_min=seg.bbox[1],
            width=seg.bbox[2],
            height=seg.bbox[3],
        )
        download_url = f"{settings.api_v1_prefix}/jobs/{job_id}/segments/{seg.index}/download"

        segments.append(SegmentResponse(
            index=seg.index,
            start_time=seg.start_time,
            end_time=seg.end_time,
            start_seconds=seg.start_seconds,
            end_seconds=seg.end_seconds,
            duration_seconds=seg.duration_seconds,
            bbox=bbox,
            download_url=download_url,
        ))

    return JobResultsResponse(
        job_id=job_id,
        status=job.status.value,
        video_metadata=video_metadata,
        detection_summary=detection_summary,
        segments=segments,
    )
```

─────────────────────────                   ─────────────────────────

result.detection.metadata.frame_count  →    video_metadata.total_frames
result.detection.metadata.duration_s   →    video_metadata.duration_seconds

result.segmentation.total_seconds_scanned  →  detection_summary.total_seconds_scanned
result.segmentation.seconds_with_detection →  detection_summary.seconds_with_detection

result.segmentation.segments[i].index          →  segments[i].index
result.segmentation.segments[i].start_time     →  segments[i].start_time
result.segmentation.segments[i].end_time       →  segments[i].end_time

## 7. Design Decisions

| Decision                                       | Rationale                                                                                          |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **`bbox` as object, not array**                | `{"x_min": 120, "y_min": 450, "width": 800, "height": 120}` is self-documenting. A raw `[120, 450, 800, 120]` array requires clients to know the index order. |
| **`download_url` is relative, not absolute**   | Works behind reverse proxies, load balancers, and different base URLs without hardcoding the host. Clients prepend the base URL themselves. |
| **409 for non-completed jobs, not 400**        | The resource exists but is in the wrong state. 409 Conflict accurately describes "this job can't produce results right now." |
| **Failed/cancelled also return 409**           | Failed jobs have no results. Cancelled jobs may have partial results but they're unreliable. Treating them uniformly as "no results" is simplest. |
| **500 for missing result data**                | If a job is `completed` but `result` is `None`, that's a server bug. 500 is appropriate, and the message helps debugging. |
| **Segment data from `segmentation.segments`**  | Not from `crop.segments`. The segmenter has the authoritative time ranges and bboxes. The cropper only adds file paths, which are internal. |

## 8. Notes

- **Stories 5.3 and 5.4** (detection timeline + detection_times.txt download) are P2. They can be added to this response later as optional fields (`detection_timeline: list[bool]` and `detection_times_url: str`) without breaking the existing schema.
- **`download_url` uses `settings.api_v1_prefix`** so it stays correct if the prefix is changed from `/api/v1` to something else.
- **Large result payloads:** A video with 100 segments produces ~100 segment objects in the JSON response. Each is ~200 bytes, so the total response is ~20 KB. Not a concern.
- **The `result` field on `Job` is typed as `Optional[object]`** in the job model. In the router we cast it to `PipelineResult`. A typed field would be better but requires importing pipeline types into the job model, creating a circular dependency. The loose typing is acceptable for MVP.
