## 1. Objective

Add environment-aware server configuration so the same codebase runs correctly in both development (laptop, `uvicorn --reload`) and production (Docker, optimized settings). Specifically:

- An `ENVIRONMENT` setting (`development` or `production`) that controls runtime behavior.
- A `run.py` entry point script that starts uvicorn with the right flags based on environment.
- Server-related settings (host, port, workers) configurable via `.env`.
- Updated Dockerfiles to use `run.py` instead of a hardcoded uvicorn CMD.
- A `.env.production` example file with recommended production values.

## 3. Detailed Implementation

### 3.1 Config Addition — `app/config.py`

Add server and environment settings to the existing `Settings` class:

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
    )

    # --- Environment ---
    environment: str = "development"  # "development" or "production"

    # --- Model & Pipeline ---
    model_path: str = "model_weights/best.pt"
    processing_mode: str = "auto"
    batch_size: int = 8
    min_segment_duration: int = 5
    crf_value: int = 16
    video_codec: str = "libx264"
    audio_codec: str = "aac"
    ffmpeg_preset: str = "veryslow"
    ffmpeg_threads: int = 4

    # --- Storage ---
    upload_dir: str = "storage/uploads"
    output_dir: str = "storage/outputs"

    # --- Upload & Validation ---
    max_upload_size_mb: int = 2048
    allowed_extensions: str = ".mp4,.avi,.mkv,.mov"

    # --- Job Management ---
    job_ttl_hours: int = 24
    max_concurrent_jobs: int = 3

    # --- Logging ---
    log_level: str = "INFO"

    # --- Server ---
    cors_origins: str = "*"
    api_v1_prefix: str = "/api/v1"
    uvicorn_host: str = "0.0.0.0"
    uvicorn_port: int = 8000

    @property
    def is_production(self) -> bool:
        return self.environment.lower() == "production"

    @property
    def max_upload_size_bytes(self) -> int:
        return self.max_upload_size_mb * 1024 * 1024

    @property
    def allowed_extensions_list(self) -> list[str]:
        return [ext.strip() for ext in self.allowed_extensions.split(",")]

    @property
    def cors_origins_list(self) -> list[str]:
        return [origin.strip() for origin in self.cors_origins.split(",")]


settings = Settings()
```

**New fields:**

| Variable        | Type  | Default           | Description                                           |
| --------------- | ----- | ----------------- | ----------------------------------------------------- |
| `ENVIRONMENT`   | `str` | `"development"`   | Runtime environment: `development` or `production`    |
| `UVICORN_HOST`  | `str` | `"0.0.0.0"`       | Host to bind uvicorn to                               |
| `UVICORN_PORT`  | `int` | `8000`            | Port to bind uvicorn to                               |

**New property:**

| Property        | Returns | Description                                          |
| --------------- | ------- | ---------------------------------------------------- |
| `is_production` | `bool`  | `True` when `ENVIRONMENT=production`                 |

### 3.2 Entry Point — `run.py`

```python
"""
Entry point for starting the JBI Detection & Segmentation API.

Configures uvicorn based on the ENVIRONMENT setting:
  - development: auto-reload, access logs, DEBUG-friendly
  - production:  no reload, no access log (structured JSON logging handles it)

Usage:
  python run.py                          # Uses defaults from .env
  ENVIRONMENT=production python run.py   # Production mode
"""

import uvicorn

from app.config import settings


def main():
    """Start uvicorn with environment-aware configuration."""
    is_prod = settings.is_production

    uvicorn_config = {
        "app": "app.main:app",
        "host": settings.uvicorn_host,
        "port": settings.uvicorn_port,
        # --- Workers ---
        # MVP uses 1 worker because the in-memory job store is per-process.
        # Multiple workers would each have their own job store, breaking
        # job status polling. When migrating to Redis/DB-backed job store,
        # increase workers to: min(2 * cpu_count + 1, 8)
        "workers": 1,
        # --- Reload ---
        # Development: watch for file changes and auto-restart.
        # Production: never reload — it disrupts active connections.
        "reload": not is_prod,
        # --- Access log ---
        # Production: disabled — Story 6.4 RequestLoggingMiddleware handles
        # request logging with request_id, timing, and JSON format.
        # Development: enabled — useful to see raw uvicorn access logs
        # alongside structured logs during debugging.
        "access_log": not is_prod,
        # --- Log level ---
        # Controls uvicorn's own logger. Application log level is set
        # separately by LOG_LEVEL via setup_logging() in Story 6.4.
        "log_level": settings.log_level.lower(),
    }

    print(
        f"Starting server — environment={settings.environment}, "
        f"host={settings.uvicorn_host}:{settings.uvicorn_port}, "
        f"reload={uvicorn_config['reload']}, "
        f"log_level={settings.log_level}"
    )

    uvicorn.run(**uvicorn_config)


if __name__ == "__main__":
    main()
```

**Behavior matrix:**

| Setting          | Development              | Production                     |
| ---------------- | ------------------------ | ------------------------------ |
| `workers`        | 1                        | 1 (MVP constraint — see note)  |
| `reload`         | `True`                   | `False`                        |
| `access_log`     | `True`                   | `False`                        |
| `log_level`      | From `LOG_LEVEL` setting | From `LOG_LEVEL` setting       |

### 3.3 Update Dockerfiles

#### `Dockerfile` (CPU)

Replace the `CMD` line:

```dockerfile
# Before (Story 7.1):
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--no-access-log"]

# After:
CMD ["python", "run.py"]
```

Also copy `run.py` into the image:

```dockerfile
# Copy application code
COPY app/ ./app/
COPY run.py .
```

#### `Dockerfile.gpu`

Same changes — replace CMD and copy `run.py`:

```dockerfile
# Copy application code
COPY app/ ./app/
COPY run.py .

# ...

CMD ["python", "run.py"]
```

The Docker environment sets `ENVIRONMENT=production` via `.env` (loaded by `env_file` in compose), so `run.py` automatically uses production settings.

**Production differences from development defaults:**

| Variable          | Development Default   | Production Recommended  | Why                                                   |
| ----------------- | --------------------- | ----------------------- | ----------------------------------------------------- |
| `ENVIRONMENT`     | `development`         | `production`            | Controls reload, access log, runtime behavior         |
| `FFMPEG_PRESET`   | `veryslow`            | `medium`                | `veryslow` produces smaller files but takes 5-10x longer. `medium` is a good balance for production throughput. |
| `CORS_ORIGINS`    | `*`                   | Specific domain(s)      | Never use `*` in production — restrict to your frontend domain. |
| `LOG_LEVEL`       | `INFO`                | `INFO`                  | Same, but can be set to `WARNING` in very high-traffic deployments to reduce log volume. |

### 3.6 Updated `Dockerfile` — Full File

```dockerfile
# ============================================================
# JBI Detection & Segmentation API — Dockerfile (CPU)
# ============================================================
# For GPU support: docker build -f Dockerfile.gpu .
# ============================================================

# --- Stage 1: Build dependencies ---
FROM python:3.11-slim AS builder

WORKDIR /build

# Install system deps needed for building Python packages
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

# Copy requirements and install into a virtualenv
COPY requirements.txt .
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
RUN pip install --no-cache-dir --upgrade pip \
    && pip install --no-cache-dir -r requirements.txt


# --- Stage 2: Runtime ---
FROM python:3.11-slim AS runtime

WORKDIR /app

# Install runtime system dependencies
RUN apt-get update && apt-get install -y --no-install-recommends \
    ffmpeg \
    libgl1 \
    libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

# Copy virtualenv from builder
COPY --from=builder /opt/venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# Copy application code and entry point
COPY app/ ./app/
COPY run.py .

# Create storage directories
RUN mkdir -p storage/uploads storage/outputs model_weights

# Expose port
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/v1/health')" || exit 1

# Start via run.py (reads ENVIRONMENT from .env / env vars)
CMD ["python", "run.py"]
```

## 5. Why Workers Must Be 1 (MVP)

The MVP uses an **in-memory job store** (`dict` protected by `threading.Lock`). This store lives inside the API process. If uvicorn runs multiple workers:

```
Worker 1 (PID 100): job_store = {"job-1": <queued>}   ← Upload lands here
Worker 2 (PID 101): job_store = {}                     ← Status poll hits here → 404!
```

Each worker process has its own memory space. Job created in worker 1 is invisible to worker 2. This means:
- `POST /api/v1/jobs` → creates job in worker 1's store
- `GET /api/v1/jobs/{id}` → may hit worker 2 → 404 Not Found

**Solution path (future):**

| Approach                      | Workers | Complexity | When to adopt                    |
| ----------------------------- | ------- | ---------- | -------------------------------- |
| **1 worker (current MVP)**     | 1       | None       | Now — sufficient for thesis      |
| **Redis-backed job store**     | N       | Medium     | When concurrent request throughput matters |
| **SQLite with WAL mode**       | N       | Low        | Quick fix if 1 worker bottlenecks |
| **Celery + Redis**             | N       | High       | Full production with task queue  |

The `run.py` hardcodes `workers=1` with a comment explaining this constraint. When the job store is externalized, change to `workers = min(2 * os.cpu_count() + 1, 8)`.

## 6. Design Decisions

| Decision                                       | Rationale                                                                                           |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **`run.py` entry point, not shell script**      | Python script can import `settings` directly. No need to parse `.env` in bash. Cross-platform (Windows + Linux). |
| **`run.py` at project root, not inside `app/`** | It's an operational script, not application code. Keeps it visible alongside `Dockerfile` and `docker-compose.yml`. |
| **`ENVIRONMENT` as a simple string**            | Two values: `development` and `production`. No need for an enum or complex hierarchy. KISS.         |
| **`is_production` property**                    | Centralizes the environment check. Modules import `settings.is_production` instead of comparing strings everywhere. |
| **Access log ON in development**                | Developers benefit from seeing raw uvicorn access logs alongside structured JSON logs. In production, they're redundant noise — Story 6.4 middleware is richer. |
| **Workers hardcoded to 1**                      | MVP in-memory job store constraint. Documented clearly with migration path. |
| **`FFMPEG_PRESET=medium` in production**        | `veryslow` is the notebook default for maximum compression. In production, encoding speed matters more — `medium` is 5-10x faster with only ~10% larger files. |
| **`.env.production` as a separate file**        | Teams can maintain environment-specific configs without overwriting each other. Docker compose loads whichever file is copied to `.env`. |

## 7. Notes

- **`run.py` replaces the Dockerfile CMD.** Both CPU and GPU Dockerfiles now use `CMD ["python", "run.py"]`. All uvicorn configuration flows through `run.py` → `settings`, making the Dockerfile simpler.
- **`uvicorn.run()` with `reload=True`** requires passing the app as a string (`"app.main:app"`) not an import. This is already handled correctly in `run.py`.
- **`--reload` watches the current directory** by default. In Docker, this is `/app/` which contains only the application code. In local development, it watches the project root which includes `app/`, `run.py`, etc. Both are fine.
- **Story 7.5** (deployment guide) will reference the `.env.production` file and the compose profile commands documented here.
- **The `print()` in `run.py`** (not `logger.info()`) is intentional. It runs before `setup_logging()` is called (logging is initialized inside `app.main` on import). Using `print()` ensures the startup banner always appears, even if logging setup fails.
