# Story 4.8 — Implement List Jobs Endpoint

## Description

Implement `GET /api/v1/jobs` to return a paginated list of all jobs, with optional filtering by status. This enables frontends and monitoring tools to display a dashboard of all jobs without requiring individual `job_id` lookups.

## Acceptance Criteria

1. **`GET /api/v1/jobs`** returns a JSON response containing an array of job summaries, total count, and pagination metadata.
2. **Status filter** — optional `status` query parameter filters jobs by state (`queued`, `processing`, `completed`, `failed`, `cancelled`). Invalid values return 400.
3. **Pagination** — `limit` (default 20, max 100) and `offset` (default 0) query parameters control result windowing.
4. **Sort order** — jobs are sorted by `created_at` descending (newest first).
5. **Response shape** — each job item includes: `job_id`, `status`, `progress` (if processing), `error` (if failed), `created_at`, `updated_at`.
6. **Empty result** — when no jobs exist or none match the filter, returns `{ "jobs": [], "total": 0, "limit": 20, "offset": 0 }`.

## API Contract

```
GET /api/v1/jobs?status=processing&limit=20&offset=0

Response 200:
{
  "jobs": [
    {
      "job_id": "abc-123",
      "status": "processing",
      "progress": { "phase": "detection", "current": 50, "total": 200, "percent": 25.0 },
      "error": null,
      "created_at": "2026-02-11T10:00:00Z",
      "updated_at": "2026-02-11T10:02:00Z"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```
