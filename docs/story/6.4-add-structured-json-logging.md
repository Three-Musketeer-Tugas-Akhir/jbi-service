---

## 1. Objective

Replace default Python `print()`-style log output with structured JSON logs so that:

- Every log line is machine-parseable (JSON object per line).
- Every HTTP request gets a unique `request_id` attached to all logs within that request.
- Job-related logs include the `job_id` for easy filtering.
- Request/response logs include method, path, status code, and duration.
- Logs are compatible with centralized logging tools (ELK, CloudWatch, Datadog, etc.).

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------- |
| AC-1 | All application logs output as single-line JSON objects.                                            |
| AC-2 | Each HTTP request generates a log entry with `request_id`, `method`, `path`, `status`, `duration_ms`. |
| AC-3 | `request_id` is a UUID generated per request and propagated to all logs within that request scope.  |
| AC-4 | Job processing logs include `job_id` field.                                                        |
| AC-5 | Log level is configurable via `LOG_LEVEL` environment variable (default: `INFO`).                  |
| AC-6 | Uvicorn access logs are disabled (replaced by the request logging middleware).                      |
| AC-7 | Startup logs show config summary (model path, processing mode, storage dirs).                      |

### 3.2 Logging Setup — `app/logging_config.py`

```python
import json
import logging
import sys
from contextvars import ContextVar
from datetime import datetime, timezone

from app.config import settings

# Context variables for request-scoped data
request_id_ctx: ContextVar[str] = ContextVar("request_id", default="")
job_id_ctx: ContextVar[str] = ContextVar("job_id", default="")


class JSONFormatter(logging.Formatter):
    """Format log records as single-line JSON objects."""

    def format(self, record: logging.LogRecord) -> str:
        log_entry = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
        }

        # Add request context if available
        req_id = request_id_ctx.get("")
        if req_id:
            log_entry["request_id"] = req_id

        # Add job context if available
        j_id = job_id_ctx.get("")
        if j_id:
            log_entry["job_id"] = j_id

        # Add exception info if present
        if record.exc_info and record.exc_info[0] is not None:
            log_entry["exception"] = self.formatException(record.exc_info)

        return json.dumps(log_entry, default=str)


def setup_logging():
    """Configure application-wide structured JSON logging."""
    level = getattr(logging, settings.log_level.upper(), logging.INFO)

    # Create JSON formatter
    formatter = JSONFormatter()

    # Configure root logger
    root = logging.getLogger()
    root.setLevel(level)

    # Remove existing handlers
    root.handlers.clear()

    # Add stdout handler with JSON formatter
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(formatter)
    root.addHandler(handler)

    # Suppress noisy third-party loggers
    logging.getLogger("uvicorn.access").setLevel(logging.WARNING)
    logging.getLogger("ultralytics").setLevel(logging.WARNING)
    logging.getLogger("moviepy").setLevel(logging.WARNING)

    logging.getLogger("app").info(
        "Logging configured — level=%s, format=JSON", settings.log_level,
    )
```

**Key design:**

- **`ContextVar`** for `request_id` and `job_id` — these are async-safe, per-coroutine variables. Set in middleware, read in the formatter.
- **`JSONFormatter`** — every log line is a complete JSON object. No multiline output.
- **Third-party loggers suppressed** — uvicorn access logs, ultralytics model loading spam, moviepy progress bars are all silenced. Our own middleware handles request logging.

### 3.3 Request Logging Middleware — `app/middleware.py`

```python
import time
import uuid
import logging

from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import Response

from app.logging_config import request_id_ctx

logger = logging.getLogger("app.requests")


class RequestLoggingMiddleware(BaseHTTPMiddleware):
    """Log every HTTP request with timing, and set request_id context."""

    async def dispatch(self, request: Request, call_next) -> Response:
        # Generate unique request ID
        req_id = str(uuid.uuid4())[:8]  # Short ID for readability
        request_id_ctx.set(req_id)

        # Record start time
        start = time.perf_counter()

        # Process request
        response = await call_next(request)

        # Calculate duration
        duration_ms = round((time.perf_counter() - start) * 1000, 1)

        # Log request summary
        logger.info(
            "%s %s → %d (%.1fms)",
            request.method,
            request.url.path,
            response.status_code,
            duration_ms,
            extra={
                "method": request.method,
                "path": request.url.path,
                "status": response.status_code,
                "duration_ms": duration_ms,
            },
        )

        # Add request ID to response headers
        response.headers["X-Request-ID"] = req_id

        return response
```

### 3.5 Wire Into App — `app/main.py`

Add logging setup and middleware:

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.config import settings
from app.routers import health, jobs
from app.services.scheduler import start_cleanup_scheduler, stop_cleanup_scheduler
from app.exception_handlers import register_exception_handlers
from app.logging_config import setup_logging
from app.middleware import RequestLoggingMiddleware

# Initialize logging before anything else
setup_logging()

import logging
logger = logging.getLogger("app")


@asynccontextmanager
async def lifespan(app: FastAPI):
    logger.info(
        "Starting JBI Detection & Segmentation API — "
        "model=%s, mode=%s, upload_dir=%s, output_dir=%s",
        settings.model_path,
        settings.processing_mode,
        settings.upload_dir,
        settings.output_dir,
    )
    start_cleanup_scheduler()
    yield
    stop_cleanup_scheduler()
    logger.info("Shutting down")


app = FastAPI(
    title="JBI Detection & Segmentation API",
    version="1.0.0",
    description="API for detecting and segmenting JBI overlays in news broadcast videos.",
    lifespan=lifespan,
)

register_exception_handlers(app)

app.add_middleware(RequestLoggingMiddleware)
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins_list,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(health.router, prefix=settings.api_v1_prefix, tags=["health"])
app.include_router(jobs.router, prefix=settings.api_v1_prefix, tags=["jobs"])


@app.get("/")
async def root():
    return {"message": "JBI Detection & Segmentation API"}
```

**Changes:**
- `setup_logging()` called before app creation.
- `RequestLoggingMiddleware` added.
- Startup log with config summary in `lifespan`.

## 6. Design Decisions

| Decision                                       | Rationale                                                                                       |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **`ContextVar` for request_id / job_id**       | Async-safe. Works with FastAPI's async handlers and background tasks without thread-local hacks. |
| **Short request ID (8 chars UUID)**            | Full UUIDs are noisy in logs. 8 hex chars = 4 billion combinations — sufficient for log correlation within a single server. |
| **Suppress uvicorn access logs**               | Our middleware provides richer request logs (timing, request_id). Uvicorn's default access log is redundant and not JSON-formatted. |
| **Suppress ultralytics / moviepy loggers**     | These libraries produce verbose output (model loading, FFmpeg progress) that drowns out application logs. Set to WARNING — errors still surface. |
| **`--no-access-log` in uvicorn command**       | Belt-and-suspenders: both programmatic suppression and CLI flag to ensure no duplicate access logs. |
| **`X-Request-ID` response header**             | Clients can report this ID when filing bugs. Support teams can grep logs by request ID instantly. |
| **`setup_logging()` before app creation**      | Ensures even startup logs are JSON-formatted. If logging is set up inside `lifespan`, pre-startup logs would be unstructured. |

---

## 7. Notes

- **No external logging libraries.** Python's built-in `logging` + a custom `JSONFormatter` is sufficient. Libraries like `structlog` or `python-json-logger` are nice but add a dependency for minimal gain at this scale.
- **Log rotation** is not handled by the application. In Docker, logs go to stdout and are managed by the container runtime (e.g. `docker logs`, CloudWatch log driver). For bare-metal, use `logrotate` or redirect to a file with `>>`.
- **`extra` fields in `logger.info()` calls** (e.g. `extra={"method": ...}`) are available but not currently included in the JSON output by the formatter. The formatter uses `record.getMessage()` which contains the formatted string. Adding `extra` fields to JSON output is a minor enhancement if needed.
- **`uvicorn app.main:app --no-access-log`** must be used when starting the server. Without it, uvicorn's default access logger will produce non-JSON lines alongside our JSON logs.
