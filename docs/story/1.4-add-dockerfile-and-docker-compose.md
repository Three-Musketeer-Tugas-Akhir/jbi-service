## 1. Objective

Create a working Docker setup that lets the team run the full service with a single `docker compose up`. This story produces:

- A `Dockerfile` that builds the FastAPI app with all CV/ML dependencies.
- A `docker-compose.yml` with three services: **api**, **worker** (placeholder), and **redis**.
- A `.dockerignore` to keep the image small.

This is the **scaffolding** version. Epic 7 stories will add CUDA GPU support (7.1), production volume mounts (7.3), and environment-based config (7.4).

## 3. Design Decisions

| Decision                                     | Rationale                                                                                            |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **CPU-only base image for now**               | `python:3.11-slim` is small and fast to build. CUDA image (nvidia/cuda) added in Story 7.1.         |
| **Multi-stage build**                         | Stage 1 installs deps into a virtualenv. Stage 2 copies only the venv + app code. Keeps image lean. |
| **Model weights via volume mount**            | `best.pt` is 6 MB+ and may change. Mounting it avoids rebuilding the image on every model update.   |
| **Redis included from day one**               | Even though MVP uses `BackgroundTasks`, having Redis ready avoids re-doing compose when Celery lands.|
| **Worker service as placeholder**             | Defined in compose but uses the same image. Will run Celery in Story 4.3.                           |
| **FFmpeg installed in image**                 | MoviePy requires FFmpeg for video encoding. Must be explicitly installed in the container.           |

## 4. Detailed Implementation

### 4.1 `Dockerfile`

```dockerfile
# ============================================================
# JBI Detection & Segmentation API — Dockerfile (CPU)
# ============================================================
# For GPU support, see Story 7.1 (nvidia/cuda base image)
# ============================================================

# --- Stage 1: Build dependencies ---
FROM python:3.11-slim AS builder

WORKDIR /build

# Install system deps needed for building Python packages
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

# Copy requirements and install into a virtualenv
COPY requirements.txt .
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
RUN pip install --no-cache-dir --upgrade pip \
    && pip install --no-cache-dir -r requirements.txt


# --- Stage 2: Runtime ---
FROM python:3.11-slim AS runtime

WORKDIR /app

# Install runtime system dependencies
RUN apt-get update && apt-get install -y --no-install-recommends \
    ffmpeg \
    libgl1 \
    libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

# Copy virtualenv from builder
COPY --from=builder /opt/venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# Copy application code
COPY app/ ./app/

# Create storage directories
RUN mkdir -p storage/uploads storage/outputs model_weights

# Expose port
EXPOSE 8000

# Health check
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/v1/health')" || exit 1

# Start uvicorn
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Notes:**

- `ffmpeg` — required by MoviePy for video encoding/decoding.
- `libgl1`, `libglib2.0-0` — required by OpenCV headless.
- Model weights are NOT copied into the image. They are mounted at runtime via docker-compose volume.

### 4.2 `docker-compose.yml`

```yaml
# ============================================================
# JBI Detection & Segmentation API — Docker Compose
# ============================================================

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    env_file:
      - .env
    volumes:
      - ./model_weights:/app/model_weights:ro
      - uploads_data:/app/storage/uploads
      - outputs_data:/app/storage/outputs
    depends_on:
      redis:
        condition: service_healthy
    restart: unless-stopped

  worker:
    build:
      context: .
      dockerfile: Dockerfile
    # Placeholder: will run Celery worker in Story 4.3
    # For now, just sleeps to keep the service defined
    command: >
      sh -c "echo 'Worker placeholder — Celery integration in Story 4.3' && sleep infinity"
    env_file:
      - .env
    volumes:
      - ./model_weights:/app/model_weights:ro
      - uploads_data:/app/storage/uploads
      - outputs_data:/app/storage/outputs
    depends_on:
      redis:
        condition: service_healthy
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 3s
      retries: 5
    restart: unless-stopped

volumes:
  uploads_data:
  outputs_data:
```

**Service breakdown:**

| Service    | Image              | Purpose                                                   |
| ---------- | ------------------ | --------------------------------------------------------- |
| `api`      | Built from Dockerfile | FastAPI server on port 8000                             |
| `worker`   | Built from Dockerfile | Placeholder for Celery worker (Story 4.3)               |
| `redis`    | `redis:7-alpine`   | Message broker for future Celery task queue               |

**Volume strategy:**

| Volume / Mount                  | Type          | Purpose                                                    |
| ------------------------------- | ------------- | ---------------------------------------------------------- |
| `./model_weights:/app/model_weights:ro` | Bind mount (read-only) | Model weights file — editable on host, no image rebuild |
| `uploads_data`                  | Named volume  | Uploaded videos — shared between api and worker            |
| `outputs_data`                  | Named volume  | Processing outputs — shared between api and worker         |

## 5. How to Verify

### 5.1 Build the image

```bash
docker build -t jbi-api .
# Should complete without errors
# Final image should be ~1.5–2 GB (PyTorch CPU is large)
```

### 5.2 Run with docker compose

```bash
# 1. Make sure .env exists (or copy from .env.example)
cp .env.example .env

# 2. Make sure model weights are in place
# (best.pt should be in model_weights/ directory)
cp best.pt model_weights/best.pt

# 3. Start all services
docker compose up --build

# Expected output:
#   redis-1   | Ready to accept connections
#   api-1     | Uvicorn running on http://0.0.0.0:8000
#   worker-1  | Worker placeholder — Celery integration in Story 4.3
```

### 5.3 Test endpoints from host

```bash
# Root
curl http://localhost:8000/
# {"message":"JBI Detection & Segmentation API"}

# Health
curl http://localhost:8000/api/v1/health
# {"status":"ok"}
```

### 5.4 Verify .dockerignore works

```bash
# Build and check that .venv, notebooks, storage are excluded
docker build -t jbi-api . 2>&1 | grep -i "sending build context"
# Context size should be small (< 50 MB without .venv and storage)
```

### 5.5 Teardown

```bash
docker compose down
# Add -v to also remove named volumes:
docker compose down -v
```

## 6. Notes

- **GPU / CUDA support** is deferred to Story 7.1. That story will create a `Dockerfile.gpu` using `nvidia/cuda:12.6.0-runtime-ubuntu22.04` as the base and add `requirements-torch-gpu.txt` to the build.
- **Worker service** does nothing yet. When Story 4.3 implements Celery, the `command` will change to `celery -A app.workers.tasks worker --loglevel=info`.
- **Named volumes** (`uploads_data`, `outputs_data`) persist across `docker compose down`. Use `docker compose down -v` to wipe them.
- **`.env` is not baked into the image** (excluded by `.dockerignore`). It's loaded at runtime via `env_file` in compose. This means secrets never end up in image layers.
