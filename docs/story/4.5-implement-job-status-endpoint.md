---

## 1. Objective

Replace the placeholder `GET /api/v1/jobs/{job_id}` stub with a fully functional status endpoint that returns:

- Current job status (`queued`, `processing`, `completed`, `failed`, `cancelled`).
- Progress details during processing (phase, current step, total, percent).
- Timestamps (`created_at`, `updated_at`).
- Error message if the job failed.

This is the primary endpoint clients poll to track job progress.

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------- |
| AC-1 | `GET /api/v1/jobs/{job_id}` returns `200` with job status, progress, and timestamps.                |
| AC-2 | Returns `404` if `job_id` does not exist.                                                           |
| AC-3 | Response includes `progress` object when status is `processing`.                                    |
| AC-4 | Response includes `error` field when status is `failed`.                                            |
| AC-5 | `progress.phase` reflects the current pipeline phase (`detection`, `segmentation`, `cropping`).     |
| AC-6 | `progress.percent` is a float 0.0–100.0.                                                           |
| AC-7 | Endpoint responds in <200ms (reads from in-memory store).                                           |

## 3. Detailed Implementation

### 3.1 Response Schemas — `app/models/schemas.py`

Add the status response models alongside the existing `JobCreateResponse`:

```python
from datetime import datetime
from typing import Optional
from pydantic import BaseModel


class JobCreateResponse(BaseModel):
    """Response for POST /api/v1/jobs."""
    job_id: str
    status: str
    created_at: datetime


class JobProgressResponse(BaseModel):
    """Progress details for a processing job."""
    phase: str
    current: int
    total: int
    percent: float


class JobStatusResponse(BaseModel):
    """Response for GET /api/v1/jobs/{job_id}."""
    job_id: str
    status: str
    progress: Optional[JobProgressResponse] = None
    error: Optional[str] = None
    created_at: datetime
    updated_at: datetime


class ErrorResponse(BaseModel):
    """Standard error response body."""
    error: str
    detail: str
```

### 3.2 Router Implementation — `app/routers/jobs.py`

Replace the `get_job_status` stub:

```python
@router.get(
    "/jobs/{job_id}",
    response_model=JobStatusResponse,
    responses={404: {"model": ErrorResponse}},
)
async def get_job_status(job_id: str):
    """Get the current status and progress of a job.

    Clients poll this endpoint to track processing progress.
    Progress details are available when status is "processing".
    Error details are available when status is "failed".
    """
    job = job_store.get(job_id)
    if not job:
        raise HTTPException(status_code=404, detail=f"Job '{job_id}' not found")

    # Build progress object only when processing
    progress = None
    if job.status == JobStatus.PROCESSING and job.progress.total > 0:
        progress = JobProgressResponse(
            phase=job.progress.phase,
            current=job.progress.current,
            total=job.progress.total,
            percent=job.progress.percent,
        )

    return JobStatusResponse(
        job_id=job.job_id,
        status=job.status.value,
        progress=progress,
        error=job.error,
        created_at=job.created_at,
        updated_at=job.updated_at,
    )
```

Add the required imports at the top of `jobs.py`:

## 5. Client Polling Pattern

Recommended client-side polling logic:

```
1. POST /api/v1/jobs → get job_id
2. Loop:
   a. GET /api/v1/jobs/{job_id}
   b. If status == "queued"     → wait 2s, repeat
   c. If status == "processing" → display progress, wait 1s, repeat
   d. If status == "completed"  → GET /api/v1/jobs/{job_id}/results → done
   e. If status == "failed"     → show error → stop
   f. If status == "cancelled"  → show cancelled → stop
```

Example client pseudocode:

```python
import time
import requests

# Step 1: Upload
resp = requests.post("http://localhost:8000/api/v1/jobs", files={"file": open("video.mp4", "rb")})
job_id = resp.json()["job_id"]

# Step 2: Poll
while True:
    resp = requests.get(f"http://localhost:8000/api/v1/jobs/{job_id}")
    data = resp.json()

    if data["status"] == "processing" and data["progress"]:
        p = data["progress"]
        print(f"[{p['phase']}] {p['percent']}%")
    elif data["status"] == "completed":
        print("Done! Fetching results...")
        break
    elif data["status"] == "failed":
        print(f"Failed: {data['error']}")
        break

    time.sleep(1)
```

## 7. Notes

- **`progress` is `null` for non-processing states.** Queued jobs haven't started yet. Completed/failed/cancelled jobs have finished — their final progress is no longer relevant.
- **`error` is `null` unless status is `failed`.** The `PipelineError` message includes the phase name (e.g. `"[detection] Cannot open video file"`), making it easy for clients to display.
- **No authentication.** Any client can poll any `job_id`. Auth is out of scope for v1 (PRD Section 11).
- **Response latency is <1ms** since it's a dict lookup. The 200ms NFR-3 target is easily met.
