## 1. Objective

Ensure that generated files, secrets, large binaries, and environment-specific artifacts are never accidentally committed. A single `.gitignore` at the project root must cover:

- Python bytecode and virtual environments
- Environment secrets (`.env`)
- Uploaded/output video files
- Model weight files (large binaries)
- IDE and OS artifacts
- Docker runtime data

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------- |
| AC-1 | `.gitignore` exists at project root.                                                           |
| AC-2 | `git status` does not show `.venv/`, `__pycache__/`, `.env`, or `storage/uploads/` contents.   |
| AC-3 | `git status` still shows tracked files: `.env.example`, `.gitkeep` files, source code.         |
| AC-4 | `model_weights/*.pt` is ignored but `model_weights/.gitkeep` is tracked.                       |

## 4. What Gets Ignored vs Tracked

| Path                              | Ignored? | Reason                                            |
| --------------------------------- | -------- | ------------------------------------------------- |
| `.venv/`                          | Yes      | Virtual environment — machine-specific             |
| `__pycache__/`                    | Yes      | Bytecode — regenerated on import                   |
| `.env`                            | Yes      | May contain secrets                                |
| `.env.example`                    | No       | Template — must be tracked                         |
| `storage/uploads/*.mp4`           | Yes      | User-uploaded videos — large, transient            |
| `storage/uploads/.gitkeep`        | No       | Keeps the directory in git                         |
| `storage/outputs/**`              | Yes      | Processing outputs — large, transient              |
| `storage/outputs/.gitkeep`        | No       | Keeps the directory in git                         |
| `model_weights/best.pt`           | Yes      | 6 MB+ binary — distributed separately              |
| `model_weights/.gitkeep`          | No       | Keeps the directory in git                         |
| `output.txt`, `output2.txt`       | Yes      | Notebook debug output — not needed in repo         |
| `object_detection_times*.txt`     | Yes      | Notebook output — transient                        |
| `app/**/*.py`                     | No       | Application source code — always tracked           |
| `requirements.txt`                | No       | Dependency manifest — always tracked               |
| `Dockerfile`, `docker-compose.yml`| No       | Infra config — always tracked                      |

## 5. How to Verify

```bash
# 1. Check that .gitignore is recognized
git status
# .gitignore should appear as a new/modified file

# 2. Verify ignored paths
git check-ignore -v .venv/
# Expected: .gitignore:X:.venv/    .venv/

git check-ignore -v .env
# Expected: .gitignore:X:.env      .env

git check-ignore -v storage/uploads/test.mp4
# Expected: .gitignore:X:storage/uploads/*    storage/uploads/test.mp4

git check-ignore -v model_weights/best.pt
# Expected: .gitignore:X:model_weights/*.pt   model_weights/best.pt

# 3. Verify .gitkeep files are NOT ignored
git check-ignore -v storage/uploads/.gitkeep
# Expected: (no output — file is NOT ignored)

git check-ignore -v model_weights/.gitkeep
# Expected: (no output — file is NOT ignored)

# 4. Verify source code is NOT ignored
git check-ignore -v app/main.py
# Expected: (no output — file is NOT ignored)
```

---

## 6. Notes

- **`best.pt` at project root** (the existing notebook model file) is NOT ignored by this `.gitignore` — only files inside `model_weights/` are. This avoids disrupting the existing notebook workflow. If you want to ignore the root `best.pt` too, add `/best.pt` to the ignore list.
- **`docker-compose.override.yml`** is ignored so developers can add local overrides (extra ports, debug env vars) without affecting the tracked compose file.
- **`.env.example`** is explicitly NOT ignored. It serves as documentation for required environment variables.
