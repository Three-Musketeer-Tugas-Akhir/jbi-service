# Story 6.1 — Add Global Exception Handlers

| Field          | Value                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------- |
| **Epic**       | 6 — API Hardening & Observability                                                                   |
| **Priority**   | P0                                                                                                 |
| **Summary**    | Add global exception handler with structured error responses + Pydantic 422 → readable messages    |
| **Depends on** | 1.1 (app entry point), all router stories (endpoints that can raise exceptions)                    |
| **Blocks**     | None (hardens all existing endpoints)                                                              |

> **Note:** Combines PRD Stories 6.1 and 6.2 — both deal with exception handling in the same module and are tightly coupled.

---

## 1. Objective

Ensure every error the API returns follows a consistent, structured JSON format. Currently:

- FastAPI's default `HTTPException` returns `{"detail": "..."}` — acceptable but inconsistent with unhandled exceptions.
- Pydantic validation errors return a deeply nested `422` body that's hard for clients to parse.
- Unhandled exceptions return FastAPI's default `500 Internal Server Error` HTML page or a generic JSON body.

After this story, all errors return:

```json
{
  "error": "<error_type>",
  "detail": "<human_readable_message>"
}
```

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------- |
| AC-1 | All `HTTPException` responses follow `{"error": "...", "detail": "..."}` format.                     |
| AC-2 | Pydantic `RequestValidationError` (422) returns `{"error": "validation_error", "detail": "..."}` with a human-readable summary of what's wrong. |
| AC-3 | Unhandled exceptions return `{"error": "internal_server_error", "detail": "An unexpected error occurred"}` with status 500. |
| AC-4 | Unhandled exceptions are logged with full traceback.                                                 |
| AC-5 | Unhandled exception detail does NOT leak stack traces, file paths, or internal state to the client.  |
| AC-6 | `404 Not Found` for unknown routes returns the structured format (not FastAPI's default).            |

## 3. Detailed Implementation

### 3.1 Exception Handlers Module — `app/exception_handlers.py`

```python
import logging
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import JSONResponse
from fastapi.exceptions import RequestValidationError

logger = logging.getLogger(__name__)


def register_exception_handlers(app: FastAPI):
    """Register all custom exception handlers on the FastAPI app."""

    @app.exception_handler(HTTPException)
    async def http_exception_handler(request: Request, exc: HTTPException):
        """Normalize HTTPException to structured format.

        FastAPI default: {"detail": "..."}
        Our format:     {"error": "...", "detail": "..."}
        """
        # Map status codes to error type names
        error_names = {
            400: "bad_request",
            404: "not_found",
            409: "conflict",
            413: "payload_too_large",
            422: "validation_error",
            429: "rate_limited",
            500: "internal_server_error",
        }
        error_type = error_names.get(exc.status_code, f"http_{exc.status_code}")

        return JSONResponse(
            status_code=exc.status_code,
            content={
                "error": error_type,
                "detail": exc.detail,
            },
        )

    @app.exception_handler(RequestValidationError)
    async def validation_exception_handler(
        request: Request, exc: RequestValidationError,
    ):
        """Convert Pydantic validation errors to a readable message.

        FastAPI default 422 body is deeply nested and hard to parse:
        {"detail": [{"loc": ["body", "file"], "msg": "...", "type": "..."}]}

        We flatten it to:
        {"error": "validation_error", "detail": "file: Field required"}
        """
        errors = exc.errors()
        messages = []

        for err in errors:
            # Build field path: ("body", "file") → "file"
            loc = err.get("loc", [])
            # Skip "body"/"query"/"path" prefixes for readability
            field_parts = [str(part) for part in loc if part not in ("body", "query", "path")]
            field = ".".join(field_parts) if field_parts else "unknown"
            msg = err.get("msg", "Invalid value")
            messages.append(f"{field}: {msg}")

        detail = "; ".join(messages)

        return JSONResponse(
            status_code=422,
            content={
                "error": "validation_error",
                "detail": detail,
            },
        )

    @app.exception_handler(Exception)
    async def unhandled_exception_handler(request: Request, exc: Exception):
        """Catch-all for unhandled exceptions.

        - Logs the full traceback for debugging.
        - Returns a generic 500 without leaking internals.
        """
        logger.exception(
            "Unhandled exception on %s %s",
            request.method, request.url.path,
        )

        return JSONResponse(
            status_code=500,
            content={
                "error": "internal_server_error",
                "detail": "An unexpected error occurred",
            },
        )
```

### 3.2 Wire Into App — `app/main.py`

Add one line after app creation:

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.config import settings
from app.routers import health, jobs
from app.services.scheduler import start_cleanup_scheduler, stop_cleanup_scheduler
from app.exception_handlers import register_exception_handlers


@asynccontextmanager
async def lifespan(app: FastAPI):
    start_cleanup_scheduler()
    yield
    stop_cleanup_scheduler()


app = FastAPI(
    title="JBI Detection & Segmentation API",
    version="1.0.0",
    description="API for detecting and segmenting JBI overlays in news broadcast videos.",
    lifespan=lifespan,
)

# Register custom exception handlers
register_exception_handlers(app)

# CORS middleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins_list,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(health.router, prefix=settings.api_v1_prefix, tags=["health"])
app.include_router(jobs.router, prefix=settings.api_v1_prefix, tags=["jobs"])


@app.get("/")
async def root():
    return {"message": "JBI Detection & Segmentation API"}
```

**Single change:** `register_exception_handlers(app)` called after app creation, before middleware.

## 4. Before vs After

### 4.1 HTTPException (400/404/409)

**Before:**
```json
{ "detail": "Job 'xxx' not found" }
```

**After:**
```json
{ "error": "not_found", "detail": "Job 'xxx' not found" }
```

### 4.2 Pydantic Validation Error (422)

**Before:**
```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "file"],
      "msg": "Field required",
      "input": null,
      "url": "https://errors.pydantic.dev/..."
    }
  ]
}
```

**After:**
```json
{
  "error": "validation_error",
  "detail": "file: Field required"
}
```

### 4.3 Unhandled Exception (500)

**Before:**
```
Internal Server Error
```
(or FastAPI's default 500 HTML/JSON)

**After:**
```json
{
  "error": "internal_server_error",
  "detail": "An unexpected error occurred"
}
```

Server logs contain the full traceback for debugging.

## 6. Design Decisions

| Decision                                        | Rationale                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Separate module (`exception_handlers.py`)**   | Keeps `main.py` clean. All error handling logic in one place.                                    |
| **`register_exception_handlers(app)` pattern**  | Function takes the app instance and registers handlers. Easy to test by passing a test app.       |
| **Flatten Pydantic errors to one string**        | Clients don't need to parse nested error arrays. A single `"field: message; field2: message2"` string is sufficient for display and logging. |
| **Strip `body`/`query`/`path` prefixes**         | `"body.file: Field required"` is noisy. `"file: Field required"` is clearer.                    |
| **Generic 500 message**                          | Never expose internal details (file paths, stack traces, library names) to clients. OWASP best practice. |
| **`error` field as snake_case type**             | Machine-readable. Clients can switch on `error` type without parsing the `detail` string.        |

## 7. Notes

- **Existing `HTTPException` calls in routers are unchanged.** The handler wraps them automatically. No router code needs modification.
- **The `ErrorResponse` Pydantic model** (created in Story 3.1) already has `error` and `detail` fields. The exception handlers now produce responses matching that schema.
- **Story 6.5 (CORS)** is already implemented in Story 1.3. No additional work needed.
- **Ordering matters:** `register_exception_handlers(app)` must be called before `add_middleware(CORSMiddleware)` so that error responses also get CORS headers.
