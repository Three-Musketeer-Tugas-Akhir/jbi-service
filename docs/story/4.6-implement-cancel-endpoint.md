## 1. Objective

Replace the placeholder `DELETE /api/v1/jobs/{job_id}` stub with a functional cancel endpoint that:

- Transitions a `queued` or `processing` job to `cancelled`.
- Returns the updated job status.
- Is rejected for jobs already in a terminal state (`completed`, `failed`, `cancelled`).
- For `processing` jobs, signals the background worker to stop cooperatively.

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------- |
| AC-1 | `DELETE /api/v1/jobs/{job_id}` returns `200` with `{"job_id": "...", "status": "cancelled"}`.       |
| AC-2 | Returns `404` if `job_id` does not exist.                                                           |
| AC-3 | Returns `409 Conflict` if job is already in a terminal state.                                       |
| AC-4 | A `queued` job transitions to `cancelled` immediately.                                              |
| AC-5 | A `processing` job transitions to `cancelled`; the background worker exits cooperatively.           |
| AC-6 | Uploaded video file for the cancelled job is cleaned up.                                            |

### 3.2 Router Implementation — `app/routers/jobs.py`

Replace the `cancel_job` stub:

```python
from app.models.schemas import (
    JobCreateResponse,
    JobStatusResponse,
    JobProgressResponse,
    JobCancelResponse,
    ErrorResponse,
)
from app.models.job import Job, JobStatus, is_terminal


@router.delete(
    "/jobs/{job_id}",
    response_model=JobCancelResponse,
    responses={
        404: {"model": ErrorResponse},
        409: {"model": ErrorResponse},
    },
)
async def cancel_job(job_id: str):
    """Cancel a queued or in-progress job.

    - Queued jobs are cancelled immediately.
    - Processing jobs are marked as cancelled; the background worker
      will detect this and stop cooperatively.
    - Jobs already in a terminal state (completed, failed, cancelled)
      cannot be cancelled and return 409 Conflict.
    """
    job = job_store.get(job_id)
    if not job:
        raise HTTPException(status_code=404, detail=f"Job '{job_id}' not found")

    if is_terminal(job.status):
        raise HTTPException(
            status_code=409,
            detail=f"Job '{job_id}' is already '{job.status.value}' and cannot be cancelled",
        )

    success = job_store.update_status(job_id, JobStatus.CANCELLED)
    if not success:
        raise HTTPException(
            status_code=409,
            detail=f"Cannot cancel job '{job_id}' in state '{job.status.value}'",
        )

    # Clean up uploaded video file
    _cleanup_upload(job.video_path)

    logger.info("Job cancelled: %s", job_id)

    return JobCancelResponse(
        job_id=job_id,
        status=JobStatus.CANCELLED.value,
    )


def _cleanup_upload(video_path: str):
    """Delete the uploaded video file if it exists."""
    try:
        path = Path(video_path)
        if path.exists():
            path.unlink()
            logger.debug("Cleaned up upload: %s", video_path)
    except OSError:
        logger.warning("Failed to clean up upload: %s", video_path)
```

### 3.3 Cooperative Cancellation in Background Worker — `app/workers/tasks.py`

The background worker checks for cancellation between pipeline phases. Update `process_job`:

```python
import logging
from app.models.job import JobStatus, is_terminal
from app.models.job_store import job_store
from app.services.pipeline import run_pipeline, PipelineError

logger = logging.getLogger(__name__)


def process_job(job_id: str, video_path: str) -> None:
    """Background task that runs the full pipeline for a job.

    Checks for cancellation via job store before and during processing.
    """
    # Check if already cancelled before starting
    job = job_store.get(job_id)
    if not job or is_terminal(job.status):
        logger.info("Job %s already in terminal state — skipping", job_id)
        return

    logger.info("Starting job %s", job_id)
    job_store.update_status(job_id, JobStatus.PROCESSING)

    def on_progress(phase, current, total):
        # Check for cancellation on each progress callback
        job = job_store.get(job_id)
        if job and job.status == JobStatus.CANCELLED:
            logger.info("Job %s cancelled during %s — aborting", job_id, phase)
            raise CancelledException(job_id)

        job_store.update_progress(job_id, phase=phase, current=current, total=total)

    try:
        result = run_pipeline(
            job_id=job_id,
            video_path=video_path,
            on_progress=on_progress,
        )
        job_store.set_result(job_id, result)
        job_store.update_status(job_id, JobStatus.COMPLETED)
        logger.info(
            "Job %s completed — %d segments",
            job_id, len(result.segmentation.segments),
        )

    except CancelledException:
        logger.info("Job %s aborted due to cancellation", job_id)
        # Status is already CANCELLED — nothing more to do

    except PipelineError as exc:
        logger.exception("Job %s failed at phase %s", job_id, exc.phase)
        job_store.update_status(job_id, JobStatus.FAILED, error=str(exc))

    except Exception as exc:
        logger.exception("Job %s failed with unexpected error", job_id)
        job_store.update_status(job_id, JobStatus.FAILED, error=str(exc))


class CancelledException(Exception):
    """Raised when a job is cancelled during processing."""

    def __init__(self, job_id: str):
        self.job_id = job_id
        super().__init__(f"Job {job_id} cancelled")
```

## 4. Cooperative Cancellation Flow

```
Client                     API                      Background Worker
  │                          │                           │
  │  DELETE /jobs/{id}       │                           │
  │─────────────────────────>│                           │
  │                          │                           │
  │                          │  job_store.update_status   │
  │                          │  → CANCELLED              │
  │                          │                           │
  │  200 {"status":          │                           │
  │       "cancelled"}       │                           │
  │<─────────────────────────│                           │
  │                          │                           │
  │                          │    ... worker still running ...
  │                          │                           │
  │                          │       on_progress() fires │
  │                          │       ├─ reads job status │
  │                          │       ├─ sees CANCELLED   │
  │                          │       └─ raises           │
  │                          │          CancelledException
  │                          │                           │
  │                          │       worker catches it   │
  │                          │       and stops cleanly   │
```

**Key behavior:**

- The cancel endpoint returns **immediately** — it does not wait for the worker to stop.
- The worker discovers the cancellation on its **next progress callback** (fired after each YOLO batch during detection).
- Worst-case latency: one batch processing time (8 seconds of video at `batch_size=8`).
- During cropping, cancellation is checked between phases (not mid-FFmpeg-export). A segment being actively exported will finish before the worker exits.

```bash
# Upload a large video to give time to cancel
JOB_ID=$(curl -s -X POST http://localhost:8000/api/v1/jobs \
  -F "file=@large_video.mp4" | python -c "import sys,json; print(json.load(sys.stdin)['job_id'])")

# Cancel immediately
curl -s -X DELETE http://localhost:8000/api/v1/jobs/$JOB_ID | python -m json.tool

# Verify status
curl -s http://localhost:8000/api/v1/jobs/$JOB_ID | python -m json.tool
```


## 7. Design Decisions

| Decision                                            | Rationale                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Cooperative cancellation via status check**       | FastAPI `BackgroundTasks` has no `task.cancel()` API. Checking job status in the progress callback is the simplest pattern. |
| **Cancel returns immediately (202-style)**          | The client doesn't need to wait for the worker to stop. Status endpoint will reflect the final state.  |
| **`CancelledException` raised in progress callback** | Cleanly unwinds the pipeline call stack. The `try/except` in `process_job` handles it without special casing in the pipeline itself. |
| **Upload file cleaned up on cancel**                | Prevents orphan files from accumulating. Output files (if any were produced during partial processing) are cleaned up by TTL (Story 4.7). |
| **409 for terminal state cancellation**             | Distinguishes "not found" (404) from "exists but can't be cancelled" (409). Prevents confusion.       |

---

## 8. Notes

- **Cancellation granularity:** During detection, the worker checks once per batch (~8 seconds of video). During cropping, it checks between phases. There is no mid-FFmpeg-export cancellation — the current segment finishes encoding before the worker exits.
- **Partial output files** from a cancelled-during-cropping job may exist in `storage/outputs/{job_id}/`. Story 4.7 (TTL cleanup) will handle deleting these.
- **Race condition:** If `DELETE` is called at the exact moment the worker transitions to `COMPLETED`, the cancel may fail with 409. This is correct behavior — the job finished successfully.
- **Future improvement:** With Celery, `task.revoke(terminate=True)` provides hard cancellation. The cooperative approach here is compatible with a Celery migration — just add `revoke` alongside the status update.
