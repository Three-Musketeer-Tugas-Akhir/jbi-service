## 1. Objective

Define a single, pinned `requirements.txt` that installs everything needed to run the FastAPI backend **and** the CV pipeline. The file must:

- Cover all direct dependencies identified from `VideoDetector3.ipynb` and the FastAPI layer.
- Pin major.minor versions (allow patch flexibility) so builds are reproducible.
- Separate PyTorch/CUDA install (handled via `--index-url`) from pure-pip packages.

## 3. Dependency Analysis

### 3.1 Dependencies from the Notebook (`VideoDetector3.ipynb`)

Traced from the notebook's imports and `%pip install` cell:

| Import / Usage                     | Package                    | Role                                   |
| ---------------------------------- | -------------------------- | -------------------------------------- |
| `from ultralytics import YOLO`     | `ultralytics`              | YOLOv8 model loading & inference       |
| `import cv2`                       | `opencv-python-headless`   | Video frame reading                    |
| `from moviepy import VideoFileClip`| `moviepy`                  | Video clipping, cropping, audio export |
| `import torch`                     | `torch`                    | GPU/CPU tensor operations              |
| `import torchvision`               | `torchvision`              | Required by ultralytics                |

> **Note:** We use `opencv-python-headless` (not `opencv-python`) because the backend has no GUI. This avoids pulling in Qt/GTK dependencies on servers.

### 3.2 New Dependencies for FastAPI Backend

| Package               | Role                                              |
| --------------------- | ------------------------------------------------- |
| `fastapi`             | Web framework                                     |
| `uvicorn[standard]`   | ASGI server (includes `uvloop`, `httptools`)       |
| `python-multipart`    | Required for `multipart/form-data` file uploads    |
| `pydantic-settings`   | Configuration management via `.env` (Story 1.3)    |

### 3.3 PyTorch + CUDA Strategy

PyTorch with CUDA support cannot be installed from the default PyPI index — it requires a special `--index-url` from `download.pytorch.org`. To keep things clean:

- **`requirements.txt`** — Lists `torch` and `torchvision` **without** CUDA suffix (defaults to CPU-only from PyPI).
- **`requirements-torch-gpu.txt`** — A separate file that installs GPU-enabled torch+torchvision via the PyTorch index. Run this **before** the main requirements file on GPU machines.

This way:
- CI/CD and CPU-only deployments just run `pip install -r requirements.txt`.
- GPU machines run `pip install -r requirements-torch-gpu.txt && pip install -r requirements.txt`.

### 4.2 `requirements-torch-gpu.txt`

```txt
# ============================================================
# PyTorch with CUDA 12.6 support
# ============================================================
# Run BEFORE requirements.txt on GPU machines:
#   pip install -r requirements-torch-gpu.txt
#   pip install -r requirements.txt

--index-url https://download.pytorch.org/whl/cu126

torch>=2.6,<3.0
torchvision>=0.21,<1.0
```

## 5. Install Instructions

### 5.1 CPU-only (development / CI)

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/Mac
source .venv/bin/activate

pip install --upgrade pip
pip install -r requirements.txt
```

### 5.2 GPU (production / local with NVIDIA GPU)

```bash
python -m venv .venv
.venv\Scripts\activate

pip install --upgrade pip
pip install -r requirements-torch-gpu.txt
pip install -r requirements.txt
```

## 6. Design Decisions

| Decision                                    | Rationale                                                                                       |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `opencv-python-headless` over `opencv-python` | No GUI needed on server. Avoids Qt/GTK dependency issues in Docker and headless environments.  |
| Separate `requirements-torch-gpu.txt`        | PyTorch CUDA builds need `--index-url` which conflicts with regular PyPI packages when mixed.   |
| Pin `>=major.minor,<next_major`              | Reproducible enough to avoid breaking changes, flexible enough to get patch/security fixes.     |
| `uvicorn[standard]` (with extras)            | Includes `uvloop` + `httptools` for better async performance in production.                     |
| `pydantic-settings` listed here              | Needed by Story 1.3 (config). Including it now avoids a second requirements edit immediately.   |

---

## 7. Notes

- **`pre_run.sh`** in the project root uses `cu130` index. The `requirements-torch-gpu.txt` uses `cu126` to match the existing `requirementx.txt` (`torch==2.10.0+cu126`). Adjust the index URL if upgrading CUDA version.
- **`requirementx.txt`** (the notebook's frozen deps) is kept as-is for notebook compatibility. The new `requirements.txt` is for the FastAPI backend only.
- Transitive dependencies (numpy, pillow, scipy, etc.) are intentionally **not** listed — they are pulled in automatically by ultralytics and moviepy. Pinning them would create unnecessary maintenance burden.
