## 1. Local Development Setup

### 1.1 Clone and enter the project

```bash
git clone <repository-url>
cd "JBI Detection & Segmentation"
```

### 1.2 Create a virtual environment

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 1.3 Install dependencies

```bash
# CPU-only (default)
pip install -r requirements.txt

# GPU (NVIDIA CUDA 12.6) — install PyTorch with CUDA first
pip install -r requirements-torch-gpu.txt
pip install -r requirements.txt
```

### 1.4 Place model weights

```bash
# Ensure best.pt exists at model_weights/best.pt
# If it's in the project root (notebook default), copy it:
mkdir -p model_weights
cp best.pt model_weights/best.pt
```

### 1.5 Configure environment (optional)

```bash
# Copy the example and edit as needed
cp .env.example .env

# All variables have sensible defaults — .env is optional for development.
```

### 1.6 Create storage directories

```bash
mkdir -p storage/uploads storage/outputs
```

### 1.7 Start the server

```bash
python run.py
```

The server starts at `http://localhost:8000` with auto-reload enabled.

### 1.8 Verify

```bash
# Root endpoint
curl http://localhost:8000/
# {"message":"JBI Detection & Segmentation API"}

# Health check
curl http://localhost:8000/api/v1/health
# {"status":"unhealthy","model_loaded":false,...}
# (model loads lazily on first job — "unhealthy" is expected here)

# Swagger UI
# Open http://localhost:8000/docs in your browser
```

## 2. Docker Deployment (CPU)

### 2.1 Prepare configuration

```bash
# Copy production config
cp .env.production .env

# Edit .env — at minimum, set:
#   ENVIRONMENT=production
#   CORS_ORIGINS=https://your-frontend.com  (or * for testing)
```

### 2.2 Ensure model weights are in place

```bash
ls model_weights/best.pt
# Should exist — it's bind-mounted into the container
```

### 2.3 Build and start

```bash
docker compose --profile cpu up --build -d
```

This starts two containers:
- `api` — FastAPI server on port 8000
- `redis` — Redis on port 6379 (for future Celery integration)

### 2.4 Verify

```bash
# Check containers are running
docker compose ps

# Health check
curl http://localhost:8000/api/v1/health

# View logs
docker compose logs -f api
```

### 2.5 Stop

```bash
# Stop containers (keep data)
docker compose --profile cpu down

# Stop and remove volumes (deletes uploaded/output files)
docker compose --profile cpu down -v
```

## 3. Docker Deployment (GPU)

### 3.1 Verify GPU access

Before building, confirm Docker can see your GPU:

```bash
docker run --rm --gpus all nvidia/cuda:12.6.3-base-ubuntu22.04 nvidia-smi
```

If this fails, install the NVIDIA Container Toolkit:

```bash
# Ubuntu
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
    | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
    | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
    | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

For **Windows (WSL2)**: Docker Desktop handles GPU passthrough natively. Ensure "Use WSL 2 based engine" is enabled in Docker Desktop settings and your NVIDIA GPU driver is up to date.

### 3.2 Prepare configuration

```bash
cp .env.production .env

# Ensure PROCESSING_MODE=auto or PROCESSING_MODE=gpu in .env
```

### 3.3 Build and start

```bash
docker compose --profile gpu up --build -d
```

This starts:
- `api-gpu` — FastAPI server with GPU access on port 8000
- `redis` — Redis on port 6379

### 3.4 Verify GPU is accessible

```bash
# Check GPU inside container
docker compose --profile gpu exec api-gpu python -c \
    "import torch; print(f'CUDA: {torch.cuda.is_available()}, Device: {torch.cuda.get_device_name(0)}')"

# Health check should show gpu_available: true
curl -s http://localhost:8000/api/v1/health | python -m json.tool
```

### 3.5 Stop

```bash
docker compose --profile gpu down
# or with volume cleanup:
docker compose --profile gpu down -v
```

## 4. Environment Configuration Reference

### Configuration files

| File               | Purpose                                  | Committed to git? |
| ------------------ | ---------------------------------------- | ------------------ |
| `.env.example`     | Development defaults with documentation  | Yes                |
| `.env.production`  | Production recommended values            | Yes                |
| `.env`             | Active configuration (loaded at runtime) | No (gitignored)   |

### Key variables

| Variable             | Dev Default          | Prod Recommended        | Notes                              |
| -------------------- | -------------------- | ----------------------- | ---------------------------------- |
| `ENVIRONMENT`        | `development`        | `production`            | Controls reload, access log        |
| `LOG_LEVEL`          | `INFO`               | `INFO`                  | `DEBUG` for troubleshooting        |
| `PROCESSING_MODE`    | `auto`               | `auto`                  | `gpu` to force GPU, `cpu` to force CPU |
| `CORS_ORIGINS`       | `*`                  | Your frontend domain(s) | Never use `*` in production        |
| `MAX_UPLOAD_SIZE_MB` | `2048`               | `2048`                  | Adjust based on expected video sizes |
| `JOB_TTL_HOURS`      | `24`                 | `24`                    | Lower for limited disk space       |
| `FFMPEG_PRESET`      | `veryslow`           | `medium`                | `medium` is 5-10x faster encoding  |
| `BATCH_SIZE`         | `8`                  | `8`                     | Increase if GPU has ample VRAM     |
| `UVICORN_PORT`       | `8000`               | `8000`                  | Change if port conflicts           |

### Override priority (highest to lowest)

1. Shell environment variable (`export LOG_LEVEL=DEBUG`)
2. `.env` file value
3. Default in `app/config.py`

## 5. End-to-End Verification Checklist

After deploying in any mode, run through this checklist to confirm everything works:

```bash
# 1. Root endpoint
curl -s http://localhost:8000/
# ✓ Returns: {"message":"JBI Detection & Segmentation API"}

# 2. Health check
curl -s http://localhost:8000/api/v1/health | python -m json.tool
# ✓ Returns JSON with status, model_loaded, gpu_available, disk_free_gb

# 3. Upload a video
curl -s -X POST http://localhost:8000/api/v1/jobs \
    -F "file=@test_video.mp4" | python -m json.tool
# ✓ Returns: job_id, status="queued", created_at

# 4. Poll job status (replace $JOB_ID with actual ID from step 3)
curl -s http://localhost:8000/api/v1/jobs/$JOB_ID | python -m json.tool
# ✓ Returns: status (queued → processing → completed)

# 5. Get results (after status=completed)
curl -s http://localhost:8000/api/v1/jobs/$JOB_ID/results | python -m json.tool
# ✓ Returns: video_metadata, detection_summary, segments[]

# 6. Download a segment
curl -o segment_000000.mp4 \
    http://localhost:8000/api/v1/jobs/$JOB_ID/segments/0/download
# ✓ Downloads MP4 file

# 7. Verify downloaded file
ffprobe -v error -show_entries stream=codec_name,width,height \
    -of default=noprint_wrappers=1 segment_000000.mp4
# ✓ Shows codec_name=h264 with width/height matching the bbox crop

# 8. Cancel a job (optional — test with a long video)
curl -s -X DELETE http://localhost:8000/api/v1/jobs/$JOB_ID | python -m json.tool
# ✓ Returns: status="cancelled"

# 9. Swagger UI
# Open http://localhost:8000/docs in your browser
# ✓ All endpoints visible and testable
```

## 6. Troubleshooting

### "Model weights not found" on startup

```
FileNotFoundError: model_weights/best.pt not found
```

**Fix:** Ensure `best.pt` is in `model_weights/` directory. For Docker, this directory is bind-mounted — the file must exist on the host:

```bash
ls model_weights/best.pt
# If missing, copy from project root:
cp best.pt model_weights/best.pt
```

### GPU not detected in Docker

```
torch.cuda.is_available() → False
```

**Checklist:**
1. Run `nvidia-smi` on the host — is the GPU driver working?
2. Run `docker run --rm --gpus all nvidia/cuda:12.6.3-base-ubuntu22.04 nvidia-smi` — does Docker see the GPU?
3. Are you using `--profile gpu` (not `--profile cpu`)?
4. Is the NVIDIA Container Toolkit installed? (see Section 3.1 above)
5. On Windows: is "Use WSL 2 based engine" enabled in Docker Desktop?

### Port 8000 already in use

```
[ERROR] Address already in use
```

**Fix:** Either stop the other process or change the port:

```bash
# Option 1: Change port in .env
UVICORN_PORT=9000

# Option 2: Change port in docker-compose
# Edit docker-compose.yml: ports: "9000:8000"
```

### Upload fails with "Payload too large"

```
413: Payload Too Large
```

**Fix:** Increase `MAX_UPLOAD_SIZE_MB` in `.env`:

```env
MAX_UPLOAD_SIZE_MB=4096  # 4 GB
```

### FFmpeg not found (local development)

```
FileNotFoundError: [Errno 2] No such file or directory: 'ffmpeg'
```

**Fix:** Install FFmpeg:

```bash
# Windows (using winget)
winget install Gyan.FFmpeg

# Windows (using chocolatey)
choco install ffmpeg

# Ubuntu/Debian
sudo apt-get install ffmpeg

# macOS
brew install ffmpeg
```

### Docker build fails on `pip install torch`

```
ERROR: Could not find a version that satisfies the requirement torch
```

**Fix:** This usually means pip is trying to build from source. Ensure the Dockerfile uses the correct requirements file:
- CPU: `requirements.txt` (includes CPU-only torch from PyPI)
- GPU: `requirements-torch-gpu.txt` first (installs from `download.pytorch.org/whl/cu126`)

### Job stuck in "processing" state

Possible causes:
1. **Video file is very large** — check progress via `GET /api/v1/jobs/{id}` (look at `percent`).
2. **FFmpeg encoding is slow** — if `FFMPEG_PRESET=veryslow`, switch to `medium` in `.env`.
3. **Out of memory** — reduce `BATCH_SIZE` in `.env` (default 8, try 4 or 2).
4. **GPU OOM** — reduce batch size or switch to CPU mode (`PROCESSING_MODE=cpu`).

### Container health check failing

```
docker compose ps
# Shows "unhealthy" status
```

This is expected on fresh start — the model loads lazily on first job. After submitting at least one job, the health check should show `model_loaded: true`. If it stays unhealthy:

```bash
# Check container logs
docker compose logs api    # or api-gpu
```

### Logs are not JSON formatted

If you see plain-text uvicorn logs instead of structured JSON:
1. Ensure `ENVIRONMENT=production` in `.env` (development mode shows both access log and JSON).
2. Ensure `run.py` is being used as the entry point (not a manual `uvicorn` command).
3. If running locally, use `python run.py` instead of `uvicorn app.main:app`.

## 7. Architecture Summary

```
┌─────────────────────────────────────────────────────────┐
│                  Client / Browser                        │
│   Upload video → Poll status → Get results → Download   │
└──────────┬──────────────────────────────────┬───────────┘
           │                                  │
           ▼                                  ▼
┌─────────────────────────────────────────────────────────┐
│              FastAPI Application (:8000)                  │
│                                                          │
│  POST /api/v1/jobs          → Upload & queue job         │
│  GET  /api/v1/jobs/{id}     → Poll status + progress     │
│  GET  /api/v1/jobs/{id}/results → Detection results      │
│  GET  /api/v1/jobs/{id}/segments/{i}/download → MP4 file │
│  DELETE /api/v1/jobs/{id}   → Cancel job                 │
│  GET  /api/v1/health        → Service health check       │
│                                                          │
│  ┌────────────────────────────────────────────────┐      │
│  │         Background Pipeline (in-process)        │      │
│  │  1. Detect (YOLO) → 2. Segment → 3. Crop (MP4) │      │
│  └────────────────────────────────────────────────┘      │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                   Storage (Disk / Volume)                 │
│                                                          │
│  model_weights/best.pt     ← YOLO model (read-only)     │
│  storage/uploads/          ← Uploaded video files        │
│  storage/outputs/{job_id}/ ← Cropped segments + metadata │
└─────────────────────────────────────────────────────────┘
```

## 5. Design Decisions

| Decision                                      | Rationale                                                                                   |
| --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **Single file (`deployment.md`), not README**  | README should be a brief project overview. Deployment details are long and warrant their own doc. README can link to it. |
| **Three deployment modes in one doc**          | Avoids scattering setup instructions across multiple files. A single doc is easier to maintain and search. |
| **Troubleshooting section included**           | Preempts support questions. Every issue listed came from real problems during development.   |
| **Quick reference table at the end**           | Experienced users skip the prose and just need the commands. The table serves as a cheat sheet. |
| **Copy-pasteable commands**                    | Commands use generic placeholders (`$JOB_ID`, `<repository-url>`) that are easy to substitute. No hidden assumptions. |

## 6. Notes

- **This story creates documentation only.** No code changes.
- **The guide assumes `best.pt` is obtained separately** (not downloaded via script). For a thesis project, the model file is typically shared via Google Drive or included in the submission. Adding a model download script is a future enhancement.
- **SSL/TLS termination** is not covered. For HTTPS in production, use a reverse proxy (nginx, Caddy, Traefik) in front of the API container. This is standard infrastructure and out of scope for the application guide.
- **CI/CD** is not covered. For a thesis project, manual `docker compose up --build` is sufficient. GitHub Actions or similar can be added later.
