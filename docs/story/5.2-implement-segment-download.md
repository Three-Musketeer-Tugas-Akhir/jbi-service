| Field          | Value                                                                                  |
| -------------- | -------------------------------------------------------------------------------------- |
| **Epic**       | 5 — Results & File Serving                                                              |
| **Priority**   | P0                                                                                     |
| **Summary**    | Stream cropped MP4 file as a download                                                  |
| **Depends on** | 5.1 (results endpoint provides `download_url`), 2.3 (cropper writes segment files)     |

---

## 1. Objective

Replace the placeholder `GET /api/v1/jobs/{job_id}/segments/{index}/download` stub with an endpoint that streams the cropped MP4 file to the client. This is the last step in the user flow: upload → poll → get results → download segments.

---

## 2. Acceptance Criteria

| #    | Criteria                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------- |
| AC-1 | `GET /api/v1/jobs/{job_id}/segments/{index}/download` streams the MP4 file with `200 OK`.             |
| AC-2 | Response `Content-Type` is `video/mp4`.                                                               |
| AC-3 | Response includes `Content-Disposition: attachment; filename="segment_000000.mp4"`.                    |
| AC-4 | Response includes `Content-Length` header for client progress bars.                                    |
| AC-5 | Returns `404` if `job_id` does not exist.                                                             |
| AC-6 | Returns `409` if job is not `completed`.                                                              |
| AC-7 | Returns `404` if segment `index` is out of range.                                                     |
| AC-8 | Returns `404` if the segment file is missing on disk (e.g. cleaned up early).                         |
| AC-9 | File is streamed (not loaded entirely into memory).                                                   |

## 3. Detailed Implementation

### 3.1 Router Implementation — `app/routers/jobs.py`

Replace the `download_segment` stub:

```python
from fastapi.responses import FileResponse
from app.services.pipeline import PipelineResult


@router.get(
    "/jobs/{job_id}/segments/{index}/download",
    responses={
        200: {"content": {"video/mp4": {}}, "description": "Cropped segment video file"},
        404: {"model": ErrorResponse},
        409: {"model": ErrorResponse},
    },
)
async def download_segment(job_id: str, index: int):
    """Download a cropped segment video file.

    Streams the MP4 file for the given segment index.
    Only available when job status is "completed".
    """
    # --- Validate job ---
    job = job_store.get(job_id)
    if not job:
        raise HTTPException(status_code=404, detail=f"Job '{job_id}' not found")

    if job.status != JobStatus.COMPLETED:
        raise HTTPException(
            status_code=409,
            detail=f"Job '{job_id}' is '{job.status.value}' — downloads are only available for completed jobs",
        )

    result: PipelineResult = job.result
    if not result:
        raise HTTPException(
            status_code=500,
            detail=f"Job '{job_id}' is completed but result data is missing",
        )

    # --- Validate segment index ---
    if index < 0 or index >= len(result.crop.segments):
        raise HTTPException(
            status_code=404,
            detail=f"Segment index {index} not found — job has {len(result.crop.segments)} segments (0–{len(result.crop.segments) - 1})",
        )

    cropped_segment = result.crop.segments[index]
    file_path = Path(cropped_segment.file_path)

    # --- Validate file exists on disk ---
    if not file_path.exists():
        logger.error(
            "Segment file missing: job=%s, index=%d, path=%s",
            job_id, index, file_path,
        )
        raise HTTPException(
            status_code=404,
            detail=f"Segment file not found on disk — it may have been cleaned up",
        )

    return FileResponse(
        path=str(file_path),
        media_type="video/mp4",
        filename=cropped_segment.file_name,
    )
```

## 4. Response Behavior

### 4.1 Success — file streamed

```
GET /api/v1/jobs/550e8400-.../segments/0/download

HTTP/1.1 200 OK
Content-Type: video/mp4
Content-Disposition: attachment; filename="segment_000000.mp4"
Content-Length: 2458632

<binary MP4 data>
```

`FileResponse` handles:
- **`Content-Type: video/mp4`** — from the `media_type` parameter.
- **`Content-Disposition: attachment; filename="..."`** — from the `filename` parameter. Triggers a download dialog in browsers.
- **`Content-Length`** — FastAPI's `FileResponse` reads the file size and sets this automatically.
- **Streaming** — `FileResponse` uses `aiofiles` under the hood to stream the file in chunks, not load it all into memory.

## 5. Error Responses

| Scenario                     | Status | Response body                                                                    |
| ---------------------------- | ------ | -------------------------------------------------------------------------------- |
| Job not found                | 404    | `{"detail": "Job 'xxx' not found"}`                                              |
| Job not completed            | 409    | `{"detail": "Job 'xxx' is 'processing' — downloads are only available for completed jobs"}` |
| Segment index out of range   | 404    | `{"detail": "Segment index 5 not found — job has 3 segments (0–2)"}`             |
| Segment index negative       | 404    | `{"detail": "Segment index -1 not found — job has 3 segments (0–2)"}`            |
| File missing on disk         | 404    | `{"detail": "Segment file not found on disk — it may have been cleaned up"}`     |
| Result data missing          | 500    | `{"detail": "Job 'xxx' is completed but result data is missing"}`                |

## 6. How to Verify

### 6.1 Full end-to-end flow

```bash
# 1. Upload
JOB_ID=$(curl -s -X POST http://localhost:8000/api/v1/jobs \
  -F "file=@test_video.mp4" | python -c "import sys,json; print(json.load(sys.stdin)['job_id'])")

# 2. Wait for completion
while true; do
  STATUS=$(curl -s http://localhost:8000/api/v1/jobs/$JOB_ID \
    | python -c "import sys,json; print(json.load(sys.stdin)['status'])")
  echo "Status: $STATUS"
  if [ "$STATUS" = "completed" ]; then break; fi
  sleep 2
done

# 3. Get results → find download URLs
curl -s http://localhost:8000/api/v1/jobs/$JOB_ID/results \
  | python -c "
import sys, json
data = json.load(sys.stdin)
for seg in data['segments']:
    print(f\"Segment {seg['index']}: {seg['download_url']}\")
"

# 4. Download first segment
curl -o segment_000000.mp4 \
  http://localhost:8000/api/v1/jobs/$JOB_ID/segments/0/download

# 5. Verify downloaded file
ffprobe -v error -show_entries stream=codec_name,width,height \
  -of default=noprint_wrappers=1 segment_000000.mp4
# Expected: codec_name=h264, width/height matching bbox
```

## 7. Design Decisions

| Decision                               | Rationale                                                                                        |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **`FileResponse` (not `StreamingResponse`)** | `FileResponse` is purpose-built for serving files. It handles `Content-Length`, `Content-Disposition`, and async streaming automatically. `StreamingResponse` would require manually reading chunks and doesn't set `Content-Length`. |
| **`filename` in Content-Disposition**  | Uses the predictable `segment_000000.mp4` name from the cropper. Clients get a meaningful filename on download instead of a UUID. |
| **Index validated against `crop.segments` length** | The segment list in `PipelineResult` is the source of truth for which files exist. |
| **404 for missing file (not 500)**     | From the client's perspective, the segment is "not found." The 500 alternative implies a server bug, but the file may have been legitimately cleaned up by TTL. The error message clarifies. |
| **409 reused for non-completed jobs**  | Same pattern as Story 5.1. Consistent error handling across the results/download endpoints. |

---

## 8. Notes

- **`FileResponse` requires `aiofiles`** for async file streaming. It's included in `uvicorn[standard]` (installed in Story 1.2). If running uvicorn without `[standard]`, add `aiofiles` to `requirements.txt`.
- **Range requests (partial content)** are NOT supported by `FileResponse`. If a client wants to resume a download, they'd need to re-request the full file. Adding range support (`Accept-Ranges`, `206 Partial Content`) is a future enhancement.
- **Concurrent downloads** of the same file are safe — `FileResponse` opens the file read-only. Multiple clients can download the same segment simultaneously.
- **Stories 5.3 and 5.4** (detection timeline + detection_times.txt download) follow the same pattern: validate job → check completed → serve data. They can be added as separate endpoints without modifying this one.
